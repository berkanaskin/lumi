## Component Interactions

### Search Input & Autocomplete

**Desktop:**
- Click or focus on search input → dropdown opens immediately, showing recent suggestions
- Type → debounce 300ms, then fetch autocomplete (title + actor + genre suggestions with poster thumbnails)
- Arrow keys: Up/Down navigate suggestions, Enter selects, Escape closes
- Click outside → dropdown closes
- Hover on suggestion → highlight with accent color, show full title
- Click suggestion → populate input and optionally submit search (UX TBD in planning)

**Mobile:**
- Tap search input → soft keyboard opens, dropdown appears below
- Swipe down in dropdown → dismiss keyboard, focus remains on input
- Same keyboard navigation as desktop (arrow keys, Enter, Escape)

**Interaction speed:**
- Autocomplete API call: <300ms (cached TMDB suggestions, lightweight)
- Visual response: 150ms fade-in on dropdown
- Suggestion hover highlight: 150ms color transition

**Source:** Extends Phase 1 existing autocomplete in `src/features/search.js` (enhanced per CONTEXT.md "faster, prettier, poster thumbnails").

---

### Search Results — Infinite Scroll

**Flow:**
1. User submits query (Enter or click Search button) → 12 results load (poster grid)
2. Results show: poster + title + year + genre tags + TMDB rating
3. User scrolls → bottom of list detected
4. "Load More" button appears or auto-load next 12 results
5. New results fade in 300ms
6. Repeat

**Loading indicator:**
- Spinner appears centered below last visible card
- "Loading..." text (14px label color) below spinner
- Spinner disappears when results arrive

**Empty results fallback:**
- If query returns 0 results, show empty state (see Copywriting Contract)
- Display 2-3 example queries user can click to try
- No error toast (graceful degradation)

**Infinite scroll threshold:**
- Trigger load when user reaches 85% of list scroll depth (not at absolute bottom)
- This ensures smooth loading before visible list ends

**Source:** Per CONTEXT.md "Infinite scroll: First 12 results load, more load as user scrolls down."

### Diversity Injection Section ("You Might Also Like")

**Visual treatment:**
- Separate section below primary results (clear visual break with lg spacing)
- Section header: "Belki de bunu beğenirsin" (Turkish friendly) / "You Might Also Like" (English)
- Same poster grid as primary results (2 columns mobile, 3 tablet, 4+ desktop)
- Results labeled as "Explore" or "Outside Your Usual Genres" (subtle label, 14px muted color)
- Optional "Explore More" button at section footer if space allows

**Content:**
- 6-8 result cards (smaller section than primary)
- Results are intentionally from genres outside user's typical watches
- Still relevant (powered by diversity injection algorithm, not random)
- User can interact same as primary results (click to detail, add to watchlist, etc.)

**Interaction:**
- Same poster hover effect as Phase 1 (scale 1.05x + overlay reveal)
- Same click-to-detail behavior
- No "dismiss" or "don't show this again" button (non-destructive exploration section)

**Source:** Per CONTEXT.md "Diversity injection in separate section: 'Belki de bunu beğenirsin' / 'You might also like' section with results outside user's typical genres."

## Accessibility & Inclusive Design

| Requirement | Implementation for Phase 2 |
|-------------|----------------------------|
| Color contrast | All text meets WCAG AA (4.5:1 body, 3:1 large text). Accent #5858f3 on dark #0a0a0f verified in Phase 1. |
| Touch targets | Search input ≥ 44px height, autocomplete items ≥ 40px, "Load More" button ≥ 44px × 44px. |
| Keyboard navigation | Tab through search input → submit button → first result → infinite scroll load button. Arrow keys navigate autocomplete. Escape closes dropdown. Enter selects. |
| Focus indicators | Visible 2px accent color (#5858f3) border on search input, buttons, autocomplete items. Focus ring respected in light theme. |
| Icon labeling | Material Symbols icons paired with text (e.g., "Search" button has icon + label). Cost dashboard icons (warning, info) have title attributes. |
| Alt text | All poster images have alt text: `[Title] - [Year]` (e.g., "Oppenheimer - 2023"). |
| Reduced motion | Respect `prefers-reduced-motion` media query. Skip autocomplete fade-in, result loading animations if requested. Keep essential transitions (page load). |
| Language support | English and Turkish. All search copy, empty states, error messages defined in i18n.js. No hardcoded strings in JS/HTML. |
| Search form semantics | Semantic HTML: `<form role="search">`, `<input type="search">`, proper `<button>` elements. Screen readers announce "Search" landmark. |
| Live regions | Use `aria-live="polite"` on loading spinner and "Load More" trigger to announce new results loading. Results grid landmark: `<section aria-label="Search Results">`. |
| Error announcements | Errors in search show toast or inline message with `role="alert"` for screen reader announcement. |

**Source:** Inherited from Phase 1 accessibility contract. No additional requirements for Phase 2 search UI beyond standard form semantics.
