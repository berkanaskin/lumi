# Phase 4.6 Plan 04.6-02: OMDB+TMDB grounded trivia — Summary

Replaced the pure-Gemini trivia call that hallucinated awards, dates, and cast with a strict grounded prompt that embeds OMDB + TMDB facts as JSON and forbids invention. Gemini may only format the supplied bundle; if uncertain it returns the sentinel `no notable trivia available`.

## Final Gemini prompt template (verbatim, for audit)

```
You are a movie trivia formatter for the Lumi app.

TITLE: {ground.facts.title}
TYPE: {movie|series}
GROUND_TRUTH_SOURCE: {omdb+tmdb|tmdb-only}

Use ONLY these facts. If unsure, say 'no notable trivia available'. Never invent awards, dates, names, or events.

Output format: ≤3 short bullets, each ≤140 characters, each verifiable from GROUND_TRUTH below.
- Begin each bullet with "• ".
- Do not output any preamble, headings, or numbers — bullets only.
- If GROUND_TRUTH lacks at least one non-obvious interesting fact, return exactly: no notable trivia available

GROUND_TRUTH:
{JSON.stringify(facts, null, 2)}
```

Five literal instruction strings are tested as a regression guard against accidental softening:
`Use ONLY these facts` · `If unsure, say 'no notable trivia available'` · `Never invent awards, dates, names, or events` · `≤3 short bullets` · the JSON ground-truth payload.

When OMDB is unavailable (rate-limit, niche title, error envelope), `source` flips to `tmdb-only` and the OMDB-side keys (`awards`, `plot`, `ratings`, `director`, `writer`, `runtime`, `released`, `country`, `language`, `box_office`) are omitted. TMDB-side keys remain.

## Degrade chain (decision table)

| OMDB result            | Gemini result | Rendered output                                                |
| ---------------------- | ------------- | -------------------------------------------------------------- |
| 200 + real data        | bullets       | ≤3 bullets + "Source: OMDB + TMDB"                             |
| null / 429 / 5xx       | bullets       | ≤3 bullets (from TMDB-only ground) + "Source: TMDB"            |
| 200 + Response:"False" | bullets       | TMDB-only path                                                 |
| any                    | sentinel      | "No notable trivia available." + correct attribution           |
| any                    | network error | "Trivia unavailable." placeholder, no error UI, no console toast |

## api/omdb.js hardening

- 8 s `AbortController` timeout → `{ error: 'timeout' }` (504)
- `429` → `{ error: 'rate_limited' }`
- `5xx` → `{ error: 'upstream_5xx' }` (502)
- Accepts both `?imdbId=` (legacy) and `?i=` (new, OMDB-native)
- Validates `^tt\d{5,}$` before upstream call (saves quota on bad input)
- `runtime: 'edge'` preserved

## Deviations from plan

1. **Task 2.3 (Mobile QA spot-check) deferred.**
   - Plan task is a `checkpoint:human-verify` requiring a live OMDB key + browser session against 5 scenarios (Inception, niche title, TV series, OMDB blocked, Gemini blocked). The execution environment has neither a populated `OMDB_API_KEY` nor a runnable Vite dev server. Per the spawn directive ("execute end-to-end … if hit ambiguity, make the most conservative choice and document"), the gate is documented here for the human operator to run at their convenience. All 5 scenarios are deterministically reproducible:
     - Scenarios A/B/C: unit-tested at compute level (`computeTriviaRender`) — the rendered output mirrors `bullets[]` + attribution.
     - Scenario D (OMDB blocked): covered by `buildTriviaPromptFor` with null/error-envelope OMDB.
     - Scenario E (Gemini blocked): covered by the `!res.ok` branch in `loadTrivia` → `TRIVIA_UNAVAILABLE_HTML`.

2. **[Rule 3 — Blocking] Extracted `computeTriviaRender` + `buildTriviaPromptFor` as exports.**
   - Plan said "use JSDOM if needed". To avoid a new JSDOM dependency and keep tests deterministic, extracted two pure compute helpers from `loadTrivia` and exported them. Same behavioral contract; loader still drives them. Adds testability without runtime cost.

3. **api/omdb.js accepts both `?imdbId=` and `?i=`.**
   - The legacy endpoint used `?imdbId=` (current code); OMDB's native param is `?i=`. Accepting both preserves backward compatibility (any future call sites using the old param continue to work) and matches the loader's new `?i=` call. Documented for transparency.
