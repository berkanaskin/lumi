# Phase 4.6: Data Sources & Onboarding Refactor — Context

**Inserted:** 2026-05-15
**Position:** Between Phase 4 (Global Foundation, code-complete) and Phase 5 (Premium Agent)
**Status:** Ready to plan

## Why this phase exists

Phase 4's onboarding wizard (Plan 04-04) shipped through r1→r7 polish rounds but surfaced systemic data-quality issues that block store-ready launch:

1. **Platform listing chaos** — TMDB-only data source produced regional cross-contamination (Epix appearing in TR list, niche services dominating non-TR regions). User-visible quality bug.
2. **Trivia hallucination** — Detail pages call Gemini for trivia without factual grounding. Gemini fabricates plausible-but-wrong facts. App Store review risk + brand damage risk.
3. **Onboarding flow friction** — Current 6-slide flow has redundant manual choices when auto-detection is already accurate. S6 finalize button is buggy. Locale switch on S2 doesn't propagate cleanly.
4. **Atil API surface** — The repo ships `api/streaming-availability.js` (RapidAPI) + `api/omdb.js` proxies that were built but never wired. We're paying TMDB-only tax while alternatives sit unused.

## Phase boundary

Make Lumi's onboarding + data layer store-ready.

**In scope:**
- Per-region curated platform dictionary (13 regions, locked in `.planning/decisions/REGION-PLATFORMS-DRAFT.md`).
- Streaming-Availability API activation (RapidAPI proxy already exists) with cost-aware caching.
- OMDB-grounded trivia (OMDB awards/plot/ratings + TMDB keywords/cast → Gemini formats, never invents).
- Onboarding hybrid auto-detect with confirmable banner (6→4 slides).
- S6 final CTA fix.

**Out of scope (deferred to Phase 5):**
- Premium feature gating (Decide-for-Me, Pair Mode, Smart Notifications, Evening Assistant).
- RevenueCat purchase flow.
- Push notification infrastructure.

**Out of scope (deferred to Phase 6):**
- iOS/Android Capacitor wrappers.
- App Store / Play Console submission assets.
