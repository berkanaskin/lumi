## providers-resolver decision table

| Curated[country] | SA available     | TMDB available | Output                                                |
| ---------------- | ---------------- | -------------- | ----------------------------------------------------- |
| len > 0          | yes              | (ignored)      | Curated, in curated order, `live` annotated true/false |
| len > 0          | null (429/5xx)   | (ignored)      | Curated, in curated order, `live=null` everywhere     |
| len > 0          | throws           | (ignored)      | Curated, silent degrade (try/catch around SA call)    |
| len === 0 (XX)   | (ignored)        | yes            | TMDB top-20, source='tmdb-fallback'                   |
| len === 0 (XX)   | (ignored)        | empty/error    | FALLBACK_PLATFORMS (6 universal entries)              |

## SA cache strategy

- **Backend:** In-memory `Map<cacheKey, {v, expiresAt}>`.
- **Key:** `sa:providers:{country.lower}:{type.lower}` (e.g. `sa:providers:tr:movie`)
- **TTL:** 24h (overridable via `setCacheTTL(ms)` test seam)
- **Failure semantics:** 429 / 5xx / timeout → returns `null`, no cache write (no negative caching → next call retries)
- **Edge layer:** `/api/streaming-availability` 200 responses now emit `Cache-Control: public, s-maxage=86400, stale-while-revalidate=43200`. Errors emit `no-store`.

## SA proxy: response schema (resolved open question #1)

Per-title (`?imdbId&country`, legacy): unchanged — `{ options: [{ service, type, link, quality? }], fetchedAt }`.

Per-region (`?mode=providers&country&type`, new): maps SA `/countries/{cc}` upstream → `{ services: { [id]: {name} } }` to the same `{ options: [{ service: { id, name } }], fetchedAt }` envelope. Consumers handle one shape.

## `@vercel/functions` runtime cache (resolved open question #2)

Not installed in `package.json`. Chose in-memory `Map` fallback — keeps tests deterministic and avoids a new dep at this stage. Vercel edge already caches per-region at the CDN tier via `s-maxage=86400`, so the client-side cache is a secondary layer (same 24h TTL). Follow-up: if SWR observability becomes important, add `@vercel/functions` and swap the wrapper.

## TTL justification (resolved open question #3)

24h is the documented PLAN target and matches SA's "platform catalogue" change frequency (platform additions/removals happen weekly-monthly, never minutely). Combined with edge `s-maxage=86400`, a region's full catalogue costs at most 1 SA call per day per edge node — well within free-tier quota.

## Deviations from plan

1. **[Rule 1 - Bug] turkish-platform-catalog.json was NOT deleted (plan A5 misread).**
   - The JSON file maps TMDB title-IDs → which TR platform streams them (used by streaming-cache.js as a curated TR title overlay). It is a *title-level* lookup, NOT a *regional provider list*. Deleting it would break TR-title platform detection. Kept as-is.

2. **[Rule 2 - Critical] Hard-fail logo existence test from soft-warn.**
   - Plan said add smoke test; original draft kept it soft. Hardened to hard-fail after Task 1.4 generated placeholders, so any future region addition without a logo blocks merge.

3. **[Rule 3 - Blocking] Real brand-asset logos cannot be acquired offline.**
   - Generated colour-coded SVG placeholders to unblock UI + tests. Documented gap above. Task 1.4 plan listed "TMDB CDN / press kit" as logo sources — neither is reachable from this build environment.

4. **TR draft order vs onboarding test order.**
   - The 2026-05-15 draft updated TR to drop BluTV and add HBO Max. Our REGION_PLATFORMS.TR follows the draft. The legacy `onboarding-platforms.test.js` expected TMDB-id 1968 (Gain) plus old TR_CURATED — its assertions still pass because `getCuratedProviders('TR')` returns the same 11 IDs (the new dict contains 8, 337, 119, 1899, 350, 11, 1968, 1888, 1855, 2895, 2864 — identical to legacy).

5. **detail.js wire-in via filter, not full resolver replacement.**
   - Plan said "replace TMDB-direct call". The detail page actually uses `getStreamingWithCache` (a separate service that already merges TMDB + SA + Firestore cache). Replacing that wholesale risked regressing the streaming-cache pipeline. Instead, applied `filterProvidersToCurated()` to its output — same end-user contract (overlay shows curated list in curated order) with zero risk to the cache layer.
