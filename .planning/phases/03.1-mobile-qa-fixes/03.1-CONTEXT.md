# Phase 03.1: Mobile QA Fixes - Context

**Gathered:** 2026-03-27
**Status:** Ready for planning
**Source:** User mobile QA session

**IMPORTANT: Lumi is now mobile-only. Desktop version cancelled entirely.**

<domain>
## Phase Boundary

Fix all 11 mobile bugs discovered during hands-on QA before proceeding to Phase 4 (Premium Platform). The app must be stable, polished, and fully functional on mobile before adding new features.

</domain>

<decisions>
## Implementation Decisions

### Critical Bugs (App-Breaking)
- **Scroll lock after modal close:** When user opens a detail modal and closes it, the entire app loses scroll ability. This is the #1 priority — makes the app unusable.
- **Search autocomplete dropdown missing:** Earlier versions had a nice dropdown appearing while typing in search. It's completely gone now. Must be restored.
- **Discover screen broken:** All suggestion buttons except "Sürpriz Yap" are non-functional. The results screen title goes under the Lumi header and becomes unreadable.

### Important UX Issues
- **Stuck shimmer on detail page:** Between the title/genre/photo block and the like buttons, there's a perpetually loading shimmer strip. Nothing ever loads there — remove it entirely.
- **Detail modal top gap:** When detail page opens, a small Lumi header piece is visible at the top. The modal should fill the entire viewport top-to-top since it has its own close (X) button.
- **Country name localization:** Shows "Turkey" instead of "Türkiye" when no streaming providers found. Check and fix all similar country name issues.
- **Notification system broken:** Needs full debugging — identify all issues and make it work reliably.

### Structural Changes
- **Remove all test user mechanisms:** Strip out all test user code, feature flags, and mock premium states. Everything should be open and functional for all users. Premium gating will be properly implemented in Phase 4 with a real admin account (username/password protected).
- **Login page disconnected:** Login page exists but is bypassed — app goes straight to home. The membership/auth system needs to be unified and consistently connected across all areas.
- **General search page evaluation:** User questions why the general search page exists separately. Evaluate whether it should be removed or merged with the main search flow.
- **Profile page buggy:** General buggy appearance and behavior needs cleanup.

### Claude's Discretion
- Technical approach to fixing scroll lock (likely body overflow/position issues from modal)
- How to restore autocomplete dropdown (check git history for previous implementation)
- Notification system debugging approach
- Whether to merge or remove the general search page

</decisions>
