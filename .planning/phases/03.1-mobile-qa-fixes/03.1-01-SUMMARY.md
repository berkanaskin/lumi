# Phase 03.1 Plan 01: Critical Mobile Bugs — Scroll Lock, Autocomplete, Discover Summary

Three app-breaking mobile bugs fixed: scroll lock after modal close, missing autocomplete dropdown, and broken discover mood chip routing.

## What Was Built

### Task 1 — Scroll lock fixed on all modal close paths (BUG-01)

The `closeModal()` function in `src/features/detail.js` already had `document.body.style.overflow = ''` and `document.body.classList.remove('modal-open')`, but was missing `document.body.style.position = ''` and `document.documentElement.style.overflow = ''` defensive resets. Both were added.

The inline script backdrop/close handlers in `index.html` had `document.body.style.overflow = ''` but were missing `document.body.classList.remove('modal-open')` (the class that drives the CSS `body.modal-open { overflow: hidden }` rule in `index_lumi.css`) and the `documentElement` reset. Both close code paths were fixed.

The `window.closeModal` override at line 2304 was also updated to include `documentElement.style.overflow = ''`.

**Commit:** `7e9d1fd`

### Task 2 — Autocomplete dropdown restored (BUG-02)

Root cause: `src/main.js` set `window.showAutocomplete = showAutocomplete` (module version expecting pre-fetched results array). The inline script also defines `showAutocomplete(query)` (correct version that fetches TMDB). After module load, the module version overwrote the inline version. The search input handler called `showAutocomplete(query)` but was getting a function that expected results — it silently failed.

Fix: Renamed to `window.showAutocompleteSuggestions = showAutocomplete` in both `src/main.js` (line 294) and `src/features/search.js` (window exports section at line 452). The inline `showAutocomplete(query)` in `index.html` now survives module load.

**Commit:** `7886f0a`

### Task 3 — Discover mood chips + results title (BUG-03)

**Part A:** The primary "Oener Bana" button called `handleAISearch()` which uses the text input and ignores mood/era chip selections. Changed to: `document.getElementById('ai-movie-input').value.trim() ? handleAISearch() : handleWizardSearch()`. When text is present, AI search runs. When only chips are selected, `handleWizardSearch()` runs (already exported to `window` from `discover.js`).

**Part B:** `.discover-results` in `index_lumi.css` had `padding-top: calc(var(--safe-top) + var(--space-lg))` — `--safe-top` may be 0 or undefined, and `--space-lg` (~24px) is insufficient to clear the 60px fixed header. Changed to `calc(var(--safe-top, 0px) + 80px)` — this gives 80px top padding (60px header + 20px breathing room) with a fallback value for `--safe-top`.

**Commit:** `9d5b44d`
