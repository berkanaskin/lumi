Fix the disconnected login flow and clean up profile page bugs.

**BUG-09 — Login wall disconnected:**

1. In `index.html`, find the `DOMContentLoaded` handler in the inline script. After the module script loads and `window.LumiModules` is available, add a call to initialize auth:
   ```javascript
   // After modules loaded:
   if (window.LumiModules && window.LumiModules.initAuth) {
     window.LumiModules.initAuth();
   }
   ```
   This ensures `initAuth()` from `profile.js` is called, which sets up the `onAuthStateChanged` listener that hides the login wall when user is already logged in.

2. Verify `initAuth()` in `src/features/profile.js` does the following:
   - Calls `firebase.auth().onAuthStateChanged(callback)`
   - In the callback: if user exists, updates `state.currentUser`, calls `hideLoginWall()`, updates profile UI
   - If user is null (logged out), shows login wall, clears state

3. Verify `hideLoginWall()` removes the `.active` class from `#login-wall` (or sets display: none). Check the login wall div in index.html (line 59) starts with `class="login-wall active"`.

4. Ensure the Google login button in the login modal calls `window.AuthService.loginWithGoogle()` and on success the `onAuthStateChanged` callback fires (which hides the wall). Remove any `location.reload()` after successful login — the SPA state should update without reload.

5. In `src/main.js`, verify `initAuth` is exported to `window.LumiModules`. If not, add it.

**BUG-11 — Profile page cleanup:**

6. Fix the stats counter: find where `stat-movies` reads from localStorage. It currently reads from `favorites` key but likes are stored in `liked_items` key. Update to read from `liked_items`:
   ```javascript
   const likedItems = JSON.parse(localStorage.getItem('liked_items') || '[]');
   document.getElementById('stat-movies').textContent = likedItems.length;
   ```

7. Fix dual auth state: ensure profile page reads from `state.currentUser` (set by `initAuth()`) consistently, NOT from `window.AuthService.getCurrentUser()`. The `state.currentUser` is the single source of truth after `initAuth()` runs.

8. Fix `updateHeaderProfileDropdown()` — it should use the same auth state as `updateAuthUI()`. If they duplicate logic, consolidate into one function called from both places.

9. Ensure profile tier badge works: after removing tester mechanisms, the tier should default to 'free' for all users. The badge should show "Free" or be hidden. Premium tier will be properly set in Phase 4.

10. Verify the bottom-nav profile page (`#view-profile`) and header profile dropdown (`#profile-dropdown`) show consistent state — same user info, same auth status.
