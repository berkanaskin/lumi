## Summary

All 11 bugs have been traced to exact code locations through source inspection. There are no external dependencies or unknown APIs involved — this is a focused internal bug-fix phase on a Vite + vanilla JS + Firebase stack.

The most serious bugs have identified root causes: scroll lock is caused by `document.body.style.overflow = 'hidden'` being set by two separate code paths (inline script and `detail.js`), but the inline script's modal-close handlers only clear `document.body.style.overflow` on `.modal-backdrop` and `.modal-close` button clicks — not on the programmatic `closeModal()` call invoked from the X button rendered inside `modal-body` by `detail.js`. The autocomplete dropdown exists and works in the inline script (`showAutocomplete()` in index.html) but there is a naming conflict: `main.js` exports `window.showAutocomplete` from `src/features/search.js`, which overwrites the inline version that does the actual rendering. The discover "Öner Bana" button calls `handleAISearch()` (AI text query) instead of `handleWizardSearch()` (mood/era chips), meaning mood and era chip selections have no functional connection to the search action.

**Primary recommendation:** Fix bugs sequentially in priority order (critical → UX → structural), using targeted edits to the exact files identified below.

### Pattern: Inline Script vs ES Module Conflict
The index.html contains a large inline `<script>` that defines functions like `showAutocomplete(query)`, `openDetailModal(id, type)`, `closeModal()`. The ES module system (`src/main.js`) exports these same names to `window.*`, which overwrites the inline versions after module load. This is the root cause of several bugs — the wrong version of a function gets called at runtime.

**Rule:** When fixing, ensure the ES module exports the correct implementation OR the inline script calls through to `window.LumiModules`.

## Bug-by-Bug Analysis

### BUG 1 — Scroll Lock After Modal Close (CRITICAL)
**File:** `src/features/detail.js` + `index.html` inline script
**Root cause:**
- `openDetail()` (detail.js:50) sets `document.body.style.overflow = 'hidden'`
- `closeModal()` (detail.js:158–180) sets `document.body.style.overflow = ''` — this is correct
- BUT: the inline script's modal-backdrop click handlers (index.html ~line 1500) also set `document.body.style.overflow = ''`
- The conflict: detail modal renders its own close (X) button inside `modal-body` via `renderDetail()`, calling `window.closeModal()`. The inline script's `.modal-close` button click handler (line ~1515) reaches `this.closest('.modal')` to find the modal but this DOM traversal may fail because `.modal-close` in `detail.js` is rendered inside `modal-body`, not directly in `.modal-content`. If the handler fails silently, `overflow = 'hidden'` is never cleared.
- **Verified:** `state.js` line 41: `countryName: 'Turkey'` — also relevant for Bug 6.
**Fix approach:** In `closeModal()` in `detail.js`, also add `document.documentElement.style.overflow = ''` and `document.body.style.position = ''` as defensive resets. Also audit whether `document.body.classList.remove('modal-open')` CSS rule applies `overflow: hidden` independently — if so, the class removal in `closeModal()` is the actual fix path.

### BUG 2 — Autocomplete Dropdown Missing (CRITICAL)
**File:** `index.html` inline script (lines ~1875–1958) + `src/features/search.js`
**Root cause:**
- `src/main.js` line 294: `window.showAutocomplete = showAutocomplete;` — this exports the ES module version from `src/features/search.js`
- The inline search input handler (index.html:1369) calls `showAutocomplete(query)` — but at this point `window.showAutocomplete` has been replaced by the module export
- The module's `showAutocomplete(results)` expects a pre-fetched results array, not a query string
- So the inline handler passes a query string to a function expecting results — it silently fails (finds 0 `.autocomplete-item` to render)
**Fix approach:** The inline script defines its own correct `showAutocomplete(query)` that fetches TMDB and renders HTML. The `main.js` export must NOT overwrite it, OR the inline version must be removed and the module version must handle query fetching. Best fix: rename the module export to `showAutocompleteSuggestions` to avoid collision, OR update the inline handler to call the module's `handleAutocomplete()` correctly.

### BUG 3 — Discover Screen Broken (CRITICAL)
**File:** `index.html` (line ~482) + `src/features/discover.js`
**Root cause (part A — mood chips non-functional):**
- The "Öner Bana" (primary) button calls `handleAISearch()` — this uses the AI text input, ignoring mood/era chip selections
- `handleWizardSearch()` in `discover.js` reads the active mood/era chips and calls `showDiscoverResults()` with the right params
- There is NO button that calls `handleWizardSearch()` in the current HTML
- Fix: Add a dedicated "Chips'e Göre Ara" button or change the primary button to call `handleWizardSearch()` when text input is empty and chips are selected, or connect chip selection to trigger automatically
**Root cause (part B — results title under header):**
- `.discover-results` CSS (index_lumi.css:1440): `padding: calc(var(--safe-top) + var(--space-lg)) ...`
- The `--safe-top` variable may not be defined or may be 0, causing the title to appear behind the fixed header (~60px tall)
- `#wizard-results-title` is inside `.discover-results-header` which has `margin-bottom` but no `padding-top` to account for header
- Fix: Ensure `padding-top` of `.discover-results` accounts for the header height (60px + safe area)

### BUG 4 — Stuck Shimmer on Detail Page
**File:** `src/features/detail.js` — `buildRatingsHTML()` (line 607–608)
**Root cause:**
```javascript
function buildRatingsHTML(tmdbScore, allRatings) {
    if (!allRatings) return '<div class="ratings-skeleton"></div>';
```
- On first render (`renderDetail` called with `null` streamingData/ratings), `allRatings` is null so a skeleton is rendered
- On second render after Phase 2 enrichment, `renderDetail` is called again with real `streamingData` but the `allRatings` field in state shows as the perpetually loading strip
- The perpetual shimmer is the `ratings-skeleton` div between title block and like buttons that never updates if `allRatings` remains null (e.g., no IMDB ID found)
**Fix:** In `buildRatingsHTML()`, when `allRatings` is null but the API call has already completed (check a flag), return empty string `''` instead of the skeleton. Alternatively, always re-render the ratings section after Phase 2 resolves.

### BUG 5 — Detail Modal Top Gap
**File:** `index.html` DOM + `src/styles/modals.css`
**Root cause:**
- The detail modal structure: `.modal` > `.modal-backdrop` (fixed full-screen) + `.modal-content`
- `.modal` (modals.css:33) has `position: relative`, `max-height: 90vh`, `border-radius: var(--radius-lg)`
- On mobile (line 49): `height: 100%`, `max-height: 100vh`, `border-radius: top-only` but still positioned inside the `.modal-backdrop` flexbox which uses `align-items: center; justify-content: center`
- The `align-items: center` on the backdrop centers the modal, leaving a visible gap at top where the fixed app header peeks through
- **Fix:** On mobile, the modal content should use `position: fixed; inset: 0; border-radius: 0` to truly fill viewport. OR the `.modal-backdrop` should use `align-items: flex-end` for mobile bottom-sheet behavior.

### BUG 6 — Country Name Shows "Turkey" Instead of "Türkiye"
**File:** `src/lib/state.js` line 41
**Root cause:**
```javascript

```
- `buildStreamingHTML()` in `detail.js` (line 671) uses `state.countryName` directly in the no-providers message
- The GeoIPService may also return country names in English
**Fix:** Change default to `'Türkiye'`. Also audit `GeoIPService` to ensure country names use endonyms or respect locale. Use an i18n-aware country name lookup rather than raw API country name strings.

### BUG 7 — Notification System Broken
**Files:** `index.html` (lines 210–234, 1156–1176)
**Root cause (multiple issues):**
1. The notification dropdown is purely static HTML — no code ever populates `#notifications-list` beyond the "Bildirim bulunmuyor" placeholder
2. `#mark-all-read` button has no event listener attached
3. The `profile-notifications-toggle` switch in the profile view (index.html line 626–633) has no event listener connected to any notification preference storage
4. There is no Firestore listener or API call that fetches user streaming drop notifications (STRM-03) — the backend infrastructure for this feature was described as "data infrastructure only" in `person.js` (line 485)
**Fix scope:** Since STRM-03 (streaming drop notifications) is a Phase 3 feature listed as Complete in REQUIREMENTS.md, the notification UI needs to actually connect to existing notification storage. The fix is to: (a) wire up `#mark-all-read` with a handler, (b) add a Firestore listener (or localStorage fallback) to populate the list, (c) wire the toggle switch to store user preference.

### BUG 9 — Login Page Disconnected (Auth Bypass)
**Files:** `index.html`, `src/features/profile.js`
**Root cause:**
- `login-wall` div starts with `class="login-wall active"` (line 59) — this is correct, it shows on load
- BUT: `initAuth()` in `profile.js` is imported in `main.js` but never called in the DOMContentLoaded flow of `index.html`
- The inline script (index.html:1278) has its own Google login handler that calls `window.AuthService.loginWithGoogle()` but then does `location.reload()` — a full page reload that should work but disconnects from SPA state
- `initAuth()` in profile.js listens to `authStateChanged` event and calls `hideLoginWall()` — but this is never initialized from the inline script context
- The inline `DOMContentLoaded` does NOT call `window.LumiModules.initAuth()`
**Fix:** In `index.html` DOMContentLoaded, after the module script loads, call `window.LumiModules.initAuth()`. Also ensure the login wall auto-hides when Firebase auth state resolves to a logged-in user on return visits.

### BUG 10 — General Search Page Evaluation
**Files:** `index.html` (search-overlay div lines ~815–900), `src/pages/search-results.js`
**Findings:**

- It has its own search grid (`#search-grid`), filter chips (All/Movies/TV/People), and infinite scroll via `search-results.js`

- **Recommendation: Keep both.** The autocomplete is for quick selection (click to open detail directly). The search overlay is for browsing a full result set with filters. Merging them would degrade UX.
- **However:** the filter chip labels are in English ("All", "Movies", "TV Shows", "People") — these need i18n keys

## Common Pitfalls

### Pitfall 1: Duplicate Function Names (window globals vs inline)
**What goes wrong:** Fixing `showAutocomplete` in the ES module while the inline script defines the same name — after module load, `window.showAutocomplete` is overwritten.
**Why it happens:** The project evolved from a single-file HTML app to an ES module system without fully migrating away from inline scripts.
**How to avoid:** For any function that exists both inline and in ES module, either: (a) remove the inline version and ensure the module version is complete, OR (b) rename the module export. Never have both active.
**Warning signs:** A function appears to work at page load but breaks after the module script executes (~100-500ms delay).

### Pitfall 2: Two Modal Close Code Paths
**What goes wrong:** Fixing scroll lock in `closeModal()` in detail.js, but the inline script's `.modal-backdrop` click handler ALSO handles close — if one path is fixed and the other isn't, the bug persists on one close method.
**How to avoid:** Fix BOTH paths: `closeModal()` in detail.js AND the inline backdrop/close button handlers. Or route all close events through a single function.

### Pitfall 3: Two Auth State Sources of Truth
**What goes wrong:** Profile UI reads from `window.AuthService.getCurrentUser()` while the app state reads from `state.currentUser` (set by profile.js) — they can be out of sync.
**How to avoid:** Always update `state.currentUser` when auth state changes. The `authStateChanged` event listener in `profile.js:initAuth()` does this correctly — just ensure it's actually called.

### Pitfall 4: Tester Code Removal Order
**What goes wrong:** Removing `handleTesterLoginFree/Premium` from profile.js before removing the `onclick="..."` HTML attributes — causes JS errors on click.
**How to avoid:** Remove HTML buttons first, then remove function implementations.

### Pitfall 5: Mobile Scroll with `position: fixed`
**What goes wrong:** Setting `body { position: fixed }` to prevent scroll (a common mobile scroll-lock technique) freezes the scroll position at top on close.
**How to avoid:** The `detail.js` approach of `overflow: hidden` is correct. The real fix is ensuring `overflow = ''` is called reliably on EVERY close path, including pressing device back button.
