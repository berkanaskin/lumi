## Human Verification Required

### 1. Modal Scroll Lock on Real Device

**Test:** Open a detail modal on a mobile browser. Close it via: (a) the X button, (b) backdrop tap. Try scrolling after each.
**Expected:** Page scrolls normally after both close paths.
**Why human:** Real-device touch events and iOS Safari's scroll quirks cannot be verified by static analysis.

### 2. Autocomplete Dropdown Rendering

**Test:** Open the app, type 3+ characters in the search bar.
**Expected:** A dropdown appears below the search input with TMDB movie/TV results. Tapping one opens the detail modal.
**Why human:** The naming collision fix is verified, but the actual DOM rendering of the dropdown and TMDB API response requires a live browser test.

### 3. Discover Mood Chip Flow

**Test:** On Discover screen, tap 2 mood chips (no text in input), tap the primary "Öner Bana" button.
**Expected:** Results appear. The results title is fully visible below the app header with no overlap.
**Why human:** The conditional routing logic is correct but the visual result title clearance depends on runtime `--safe-top` CSS variable value on the specific device.

### 4. Login Wall Auto-Hide on Session Restore

**Test:** Log in via Google. Close browser. Reopen the app.
**Expected:** Login wall auto-hides (Firebase remembers session), user sees the app directly.
**Why human:** Firebase session persistence requires a real auth environment and actual browser session storage.

### 5. Country Name After GeoIP Detection

**Test:** Open app with fresh localStorage. Wait for GeoIP detection.
**Expected:** Country displayed in streaming section shows "Türkiye" (not "Turkey") for a Turkish IP.
**Why human:** Requires GeoIP API call from Turkish IP address.
