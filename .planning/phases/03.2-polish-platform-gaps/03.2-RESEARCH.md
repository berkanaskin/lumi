## Summary

This phase has six distinct work tracks. The most critical is the streaming provider bug — Turkish users see nothing for Gain, Exxen, TV+, TOD because those platforms are not in the Streaming Availability API. BluTV is the only Turkish platform confirmed in the RapidAPI Streaming Availability dataset. The fix is a hardcoded Turkish platform fallback layer that runs after the main API, using TMDB watch providers as the data source (which does include Turkish platforms with TR region data).

The favorites bug is a confirmed localStorage key mismatch found directly in the code: `loadFavoritesList()` in index.html reads `"favorites"` and `"watchlist"` keys, but `toggleLike()` in detail.js writes to `"liked_items"` and `toggleWatchlist()` writes to `"watchlist_items"`. This single discrepancy explains why both lists appear empty.

Firebase Auth profile customization uses `currentUser.updateProfile()` for displayName and photoURL — this is the compat v8 SDK pattern already used in auth.js. For preset avatars, store the selection in Firestore `users/{uid}` since photoURL accepts a URL string.

**Primary recommendation:** Fix the localStorage key bug first (30 min, high impact), then the Turkish streaming fallback (2-3 hrs), then profile customization, then cinema badge redesign, then discover redesign.

## Streaming Providers — Root Cause Analysis

### Confirmed Finding (HIGH confidence — direct code inspection)

The `_tmdbFallback()` function in `streaming-cache.js` is already present and correct. The fallback triggers when the RapidAPI call fails (429/500), but the RapidAPI call succeeds for popular content — it returns results, just without Turkish platforms.

**The real problem:** The Streaming Availability RapidAPI (`streaming-availability.p.rapidapi.com`) only covers BluTV for Turkey. Gain, Exxen, TOD, TV+, PuhuTV do not exist in its dataset.

**Solution: Two-layer provider merge**

1. Always call TMDB `/{type}/{id}/watch/providers` for TR
2. Merge TMDB TR results INTO the RapidAPI results (not replacing them)
3. Deduplicate on `serviceId`/`provider_id`

The TMDB TR providers endpoint (`data.results['TR']`) returns `flatrate`, `free`, `rent`, `buy` arrays that include:
- Netflix, Disney+, Amazon Prime — already in RapidAPI results
- BluTV, Gain, Exxen, Tabii, TOD, beIN CONNECT — only in TMDB

### TMDB Watch Provider Structure (existing code)
```javascript
// Already in _tmdbFallback() — copy this pattern for merge
const flatList = [
    ...(tmdbProviders.flatrate || []).map(p => ({ ...p, type: 'subscription' })),
    ...(tmdbProviders.free || []).map(p => ({ ...p, type: 'free' })),
    ...(tmdbProviders.rent || []).map(p => ({ ...p, type: 'rent' })),
    ...(tmdbProviders.buy || []).map(p => ({ ...p, type: 'buy' })),
];
// provider shape: { provider_id, provider_name, logo_path, display_priority }
```

## Favorites/Watchlist Bug — Root Cause (HIGH confidence)

**Direct code evidence — key mismatch:**

| Location | Operation | localStorage Key Used |
|----------|-----------|----------------------|
| `detail.js:toggleLike()` | Write liked items | `"liked_items"` |
| `detail.js:toggleWatchlist()` | Write watchlist | `"watchlist_items"` |
| `index.html:loadFavoritesList("liked")` | Read liked items | `"favorites"` |
| `index.html:loadFavoritesList("watchlist")` | Read watchlist | `"watchlist"` |
| `profile.js:getUserStats()` | Read liked items | `"liked_items"` (correct) |

The favorites page is reading from `"favorites"` and `"watchlist"` but writes go to `"liked_items"` and `"watchlist_items"`. Legacy `toggleFavorite()` does write to `"favorites"` but is never called from the current UI.

**Fix:** Update `loadFavoritesList()` in index.html to use:
- `"liked"` tab → read `localStorage.getItem("liked_items")`
- `"watched"` tab → read `localStorage.getItem("watchlist_items")`

Also update the item shape access — `toggleLike()` stores `poster_path` (correct), `media_type`, `added_at`. The render template in `loadFavoritesList` reads `item.poster` and `item.type` — these must be fixed to `item.poster_path` and `item.media_type`.

## Common Pitfalls

### Pitfall 1: TMDB Fallback Already Exists But Not Used For Merge
**What goes wrong:** Developer adds a separate "Turkish platform" fetch instead of using the existing `_tmdbFallback` logic.
**Why it happens:** Not reading existing code carefully.
**How to avoid:** Modify `_fetchFromApiOrFallback` to always run a TMDB TR merge AFTER the RapidAPI call succeeds, not just when it fails.

### Pitfall 2: Clearing Existing Liked Items on Key Fix
**What goes wrong:** Fixing the localStorage key changes what items are read — users who had liked items in the old `"favorites"` key lose them.
**Why it happens:** Simple key rename without migration.
**How to avoid:** In `loadFavoritesList`, read BOTH keys and merge: `[...legacyItems, ...newItems]` filtered for duplicates by `id`. Then consolidate to the new key.

### Pitfall 3: Firebase updateProfile Does Not Update Immediately in compat v8
**What goes wrong:** After calling `user.updateProfile()`, reading `firebase.auth().currentUser.displayName` returns old value in some edge cases.
**Why it happens:** Firebase caches the user object.
**How to avoid:** After `updateProfile()`, explicitly call `syncUserToLocal(firebase.auth().currentUser)` and dispatch `authStateChanged` event to update all UI.

### Pitfall 4: photoURL Must Be a Valid HTTPS URL
**What goes wrong:** Storing a local blob URL or relative path as photoURL breaks across sessions.
**Why it happens:** Developer uses `URL.createObjectURL()` for file uploads.
**How to avoid:** For preset avatars, use CDN/static HTTPS URLs only. For custom uploads, upload to Firebase Storage first and use the download URL.

### Pitfall 5: Desktop CSS Removal Breaking Mobile Layout
**What goes wrong:** Removing sidebar/desktop CSS accidentally removes classes that mobile layout also references.
**Why it happens:** Shared class names between desktop and mobile variants.
**How to avoid:** Search for each class being removed in the mobile CSS context before deleting. Run `grep -r "sidebar"` etc. before removal.

## Code Examples

### Streaming Two-Layer Merge Pattern
```javascript
// Source: existing _tmdbFallback in streaming-cache.js
// Add to _fetchFromApiOrFallback — after successful RapidAPI fetch:
async function mergeWithTMDB(rapidApiProviders, tmdbId, countryUpper, type) {
    try {
        const tmdbData = await TMDBService.getWatchProviders(tmdbId, type, countryUpper);
        if (!tmdbData) return rapidApiProviders;
        const flatList = [
            ...(tmdbData.flatrate || []).map(p => ({ ...p, groupType: 'subscription' })),
            ...(tmdbData.free || []).map(p => ({ ...p, groupType: 'free' })),
        ];
        const tmdbNormalized = flatList.map(p => ({
            serviceId: String(p.provider_id),
            serviceName: p.provider_name,
            type: p.groupType,
            group: GROUP_MAP[p.groupType] || 'stream',
            link: tmdbData.link || '',
            logoPath: p.logo_path || null,
            themeColor: null, quality: null,
        }));
        // Merge: RapidAPI first (higher quality data), TMDB fills gaps
        const seen = new Set(rapidApiProviders.map(p => p.serviceId.toLowerCase()));
        const additions = tmdbNormalized.filter(p => !seen.has(p.serviceId.toLowerCase()));
        return [...rapidApiProviders, ...additions];
    } catch { return rapidApiProviders; }
}
```

### Firebase Profile Update (compat v8)
```javascript
// In auth.js — add new method:
async updateUserProfile(displayName, photoURL) {
    const user = this.auth.currentUser;
    if (!user) throw new Error('Not logged in');
    const updates = {};
    if (displayName !== undefined) updates.displayName = displayName;
    if (photoURL !== undefined) updates.photoURL = photoURL;
    await user.updateProfile(updates);
    // Sync Firestore
    if (this.db) {
        await this.db.collection('users').doc(user.uid).update(updates);
    }
    // Refresh local state
    this.syncUserToLocal(this.auth.currentUser);
}
```
