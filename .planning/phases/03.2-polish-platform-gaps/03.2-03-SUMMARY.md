# Phase 03.2 Plan 03: Profile Customization (Track E) Summary

JWT-less, Firebase compat v8 profile editing: tap-to-edit display name + 10-avatar picker bottom sheet, persisted to Firebase Auth and mirrored to Firestore `users/{uid}`, with the watch stats card reframed to draw from `liked_items` / `watchlist_items` localStorage truth.

## What Shipped

- `AuthService.updateUserProfile(displayName, photoURL)` — single-method API for both name + avatar flows. Auth-first then best-effort Firestore mirror; falls back to `set({ merge: true })` if the user doc doesn't yet exist. Calls `syncUserToLocal` and dispatches `authStateChanged` so all UI surfaces (header, profile page, dropdown) re-render automatically (Pitfall 3).
- `src/lib/avatars.js` — 10 HTTPS DiceBear avatars with movie/cinema seeds (Yıldız, Klaket, Bobin, Bilet, Sahne, Yönetmen, Sinema, Mikrofon, Galaksi, Macera) plus an `isAllowedPhotoURL` HTTPS host allowlist.
- `src/features/profile-edit.js` — ES module wiring: tap-to-edit name (Enter commits, Esc/blur cancels with revert-on-error), avatar picker bottom-sheet, auto-refresh on `authStateChanged`, `hashchange` re-stats.
- `src/styles/profile.css` — pencil edit badge, inline name input, bottom-sheet modal with handle, 5x2 avatar grid, active-tile state. Mobile-only, reuses existing design tokens.
- `index.html` — pencil overlay added to `.profile-avatar-container`, profile name made tap-target, stat cards relabeled (`İzlenen Film` → `Beğenilen` reading `liked_items`; `Toplam Süre` → `Listede Bekleyen` reading `watchlist_items`), avatar picker modal markup, profile-edit module script tag.
- `tests/profile-update.test.js` — 6 tests covering: displayName update, photoURL-only update, throws when logged out, syncUserToLocal invocation, HTTPS rejection, name trim+cap.

## Threat Mitigations Applied

| ID | Mitigation |
|----|-----------|
| T-03.2-03-01 (photoURL tampering) | Reject non-HTTPS in `updateUserProfile`; client also restricts picker URLs to allowlisted hosts via `isAllowedPhotoURL` |
| T-03.2-03-02 (XSS via displayName) | All renders use `textContent`; trim + 40-char cap before send |
| T-03.2-03-03 (Firestore authz) | `firestore.rules` already enforces `request.auth.uid == userId` for `users/{userId}` writes — no rule change needed |
| T-03.2-03-04 (info disclosure) | Accepted as documented |

## Deviations from Plan

**1. [Rule 3 — testability] Extracted `updateUserProfile` body into `src/lib/auth-update.js`**
- Found during: Task 1 RED
- Issue: `AuthService` is loaded as a non-module global script, so `tests/profile-update.test.js` cannot `import` it. Mocking the entire Firebase SDK in vitest setup is heavyweight and brittle.
- Fix: Created a pure DI helper (`updateUserProfileImpl({auth, db, syncUserToLocal}, displayName, photoURL)`) that the test imports directly. The `AuthService.updateUserProfile` method on the global class delegates to the same logic (duplicated for clarity since the class can't `import` cleanly without refactoring the script-tag loading model).
- Files: `src/lib/auth-update.js`, `public/services/auth.js`, `tests/profile-update.test.js`
- Commits: `b19385f` (RED), `0177ade` (GREEN)

**2. [Rule 2 — scope add] HTTPS host allowlist for photoURL**
- Found during: Task 2
- Issue: Plan calls only for HTTPS check, but a malicious URL on any HTTPS host could still embed tracking pixels or unexpected content.
- Fix: Added `isAllowedPhotoURL` with a small allowlist (DiceBear CDN, Google sign-in photos, TMDB CDN, pravatar). Picker only commits allowlisted URLs.
- Files: `src/lib/avatars.js`, `src/features/profile-edit.js`
- Commit: `0177ade`

**3. [Rule 2 — UX] Auth-state event listener in profile-edit.js**
- Found during: Task 3
- Issue: After `updateUserProfile`, header dropdown + auth-area must reflect new name/avatar. The existing `authStateChanged` listener in `src/features/profile.js` updates header but not the profile page identity.
- Fix: `profile-edit.js` listens to `authStateChanged` and refreshes name + avatar img + stats.
- Files: `src/features/profile-edit.js`
- Commit: `e46ed09`
